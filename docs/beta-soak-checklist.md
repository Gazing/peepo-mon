# Beta-soak verification checklist

A play-test plan for the bug-fix series (PRs #1–#25). Each fix here was verified by inspection and cross-model review, but **not** play-tested — running these on a real build is what upgrades that evidence, and is the gate before any **upstream-applicable** fixes are proposed upstream.

**How to use it:** run against a build containing every PR being marked PASS — ideally one integration build containing the complete series. For every run, record: **build SHA · tester · date · emulator/hardware · save used · evidence** (screenshot / video / savestate) for any failure.

**Note on DexNav:** no shipped event grants DexNav, so the DexNav tests below require a prepared save or the debug flag editor to set `DN_FLAG_DEXNAV_GET` (`0x021`).

Failure-record row format:

```
PR | build SHA | PASS/FAIL/N/A | map/mode | exact action | observed result | evidence link
```

## Natural-play smoke tests

- [ ] **[#8](https://github.com/Gazing/peepo-mon/pull/8) BW summary teardown** — Open, switch Pokémon, and close Summary 20–30 times; also enter and return from move-selection/relearning. **PASS:** every transition returns cleanly, correct graphics and controls. **FAIL:** any crash, hang, corruption, or dead input. (Catches regressions; cannot *prove* the former allocator-dependent memory bug absent without instrumentation.)
- [ ] **[#10](https://github.com/Gazing/peepo-mon/pull/10) New Game settings preservation** — Choose visibly non-default randomizer options and Hardcore On; enter a name; at "So it's <name>?" reject it — test **both** No and B; revisit the settings. Then soft-reset / reboot and start another New Game. **PASS:** selections survive both rejections within the attempt, and the post-reboot attempt starts at defaults. **FAIL:** settings reset after a rejection, or leak into the fresh attempt.
- [ ] **[#14](https://github.com/Gazing/peepo-mon/pull/14) No Bosses** — Start with Trainer randomization and No Bosses; confirm at least one ordinary-trainer substitution (if a trainer comes back identical, that's a valid identity mapping — do **not** fail it, try another ordinary trainer), then fight a **Gym Leader**. **PASS:** ordinary trainers are substituted while the Gym Leader keeps its authored roster. **FAIL:** a Gym Leader, Elite Four, Champion, or Magma/Aqua leader/admin receives substituted species.
- [ ] **[#16](https://github.com/Gazing/peepo-mon/pull/16) Hardcore blocked throws** — On an already-caught route, use a **one-copy** ordinary ball with neighboring pocket entries; note quantities and order. Attempt one Bag throw and one R-shortcut throw. For Safari, savestate at one ball: (a) one blocked throw then **Run** — checks the zero-ball hang; (b) reload, two blocked throws — checks the 255 wrap. **PASS:** the route message appears, ordinary-ball count and pocket order unchanged, and Safari never loses/wraps the count and exits normally. **FAIL:** consumption/reordering, Safari count loss or wrap to 255, or a hung exit.
- [ ] **[#6](https://github.com/Gazing/peepo-mon/pull/6) BW TM relearner** — With the compatible TM **owned in the Bag**, open Summary for a Pokémon with that unlearned TM but no forgotten level-up move; press START. Then open a level-up-eligible Pokémon after previously browsing a TM category. **PASS:** the first shows a prompt and opens a non-empty TM list; the second opens level-up moves, not a stale TM list. **FAIL:** missing prompt, empty/wrong category, or stale state.

## DexNav tests (require `DN_FLAG_DEXNAV_GET` = `0x021` via a prepared save or the debug flag editor)

- [ ] **[#1](https://github.com/Gazing/peepo-mon/pull/1) DexNav species consistency** — Enable **Wild/Species** randomization; perform several land DexNav searches, noting the displayed species before battle. **PASS:** every battled species exactly matches its display. **FAIL:** any mismatch. (Do not use the surfing-hidden-mon path for acceptance — that's [#20](https://github.com/Gazing/peepo-mon/pull/20).)
- [ ] **[#2](https://github.com/Gazing/peepo-mon/pull/2) DexNav approachability** — Enable auto-run and approach a land target while holding A; for the timeout, wait 3–20 tiles away with field controls unlocked (past 15 s, then around 60 s); deliberately dash-approach another. **PASS:** A creeps, the search survives past 15 s, timeout reports "got away" around 60 s, and the fast approach reports "moved too fast." **FAIL:** A runs, the search dies around 15 s, or either ending is silent. (The formerly-silent *unrevealed-hidden-mon* branches are N/A here — testing them needs synthetic hidden data plus detector mode.)
- [ ] **[#5](https://github.com/Gazing/peepo-mon/pull/5) DexNav relocation** — On open water and in a cave, creep correctly through both mid-chase relocations **with sprite/OBJ-tile capacity available**; repeat several searches. Include a cave run at a high or materially different map coordinate (covers the bundled cave-scale fix). **PASS:** relocation moves the target or deliberately leaves it in place, and the chase continues. **FAIL:** "got away" at relocation despite correct speed, range, timing, available tiles, *and* available sprite/tile capacity. (Initial-search stochastic failure is outside this PR.)
- [ ] **[#15](https://github.com/Gazing/peepo-mon/pull/15) DexNav seam race** — Beside a seamless map connection, use savestates/frame-advance to cross on each frame around the reveal transition; then begin another search. **PASS:** the crossed search cancels and **removes** its panel/icon, and the subsequent search recreates an intact panel/icon and works. **FAIL:** crash, hang, a panel/icon that persists after the cancel, a missing panel on the next search, or a blocked later search.
- [ ] **[#18](https://github.com/Gazing/peepo-mon/pull/18) Start-menu overflow** — In an ordinary overworld state with all of these set — Pokédex (`FLAG_SYS_POKEDEX_GET`), Pokémon menu (`FLAG_SYS_POKEMON_GET`), PokéNav (`FLAG_SYS_POKENAV_GET`), Badge 6 (Fly), and DexNav (`DN_FLAG_DEXNAV_GET` `0x021`) — open START. **PASS:** exactly nine visible/selectable rows, in order — Pokédex, DexNav, Fly, Pokémon, Bag, PokéNav, Player, Save, Option — with no Exit row, and both B and START close the menu. **FAIL:** soft-lock, a tenth/off-screen row, or a missing functional row.

## Directed feature tests (multiplayer + editor)

- [ ] **[#12](https://github.com/Gazing/peepo-mon/pull/12) Multiplayer battle ghost** — With two visible clients, test **voluntary leave** and **hard timeout** separately: one client enters battle while the other departs by that method; return to the field. For slot reuse, bring in a replacement peer with **visibly different** avatar/follower graphics before returning. **PASS:** the departed avatar/follower is absent, its tile is passable, and the replacement peer shows its own graphics. **FAIL:** a frozen/collidable ghost, or inherited graphics.
- [ ] **[#4](https://github.com/Gazing/peepo-mon/pull/4) Hardcore whiteout** — On a **disposable** Hardcore save, first **save successfully and confirm Continue exists** (so its later absence isn't a vacuous pass). Then white out in an ordinary wild or trainer battle (not Pyramid/Pike/Trainer Hill); dismiss the message and reboot once. **PASS:** no freeze, the message leads to the title, and Continue is absent both after the message and after reboot. **FAIL:** freeze, failed reset, or a surviving save. **Never use a valued save.**
- [ ] **[#17](https://github.com/Gazing/peepo-mon/pull/17) Strength-pushed editor boulder** — Place a boulder, exit the editor, push it with Strength, then test source and destination tiles; repeat with all eight render slots occupied if possible. **PASS:** the pushing player immediately sees the boulder move, source becomes passable, destination becomes blocked. **FAIL:** local sprite/collision remains at the source or separates. (The documented remote full-pool disappearance is deferred and must not fail this PR.)
- [ ] **[#13](https://github.com/Gazing/peepo-mon/pull/13) Steven partner battle** — On a backed-up Hardcore save, confirm an ordinary faint still releases normally. In the Mossdeep Steven battle, let one selected player Pokémon faint, win, inspect the party, then save/reload. **PASS:** the fainted Pokémon is released, all survivors belong to the player, and no Steven Pokémon appears after reload. **FAIL:** a Steven Pokémon enters the party, or the fainted Pokémon remains.
- [ ] **[#11](https://github.com/Gazing/peepo-mon/pull/11) Concurrent editor preview** — Two subcases (covering both inbound paths): (a) Client A holds a preview over one cell, Client B commits a visibly different tile/wall to that exact cell, A moves the cursor or exits and checks collision; (b) trigger a **delayed snapshot replay** that repaints the previewed cell while A's preview is up (e.g. A re-enters the map / re-requests a snapshot), then A moves or exits. **PASS:** the inbound tile's appearance and collision remain on A in both subcases. **FAIL:** A restores the old tile or collision locally.
- [ ] **[#9](https://github.com/Gazing/peepo-mon/pull/9) Editor spawn exhaustion** — Leave a map-editor render slot free while exhausting the engine object-event or sprite pool (crowd the map with NPCs/remotes). Bring a placed boulder/tree/rock into range that can't spawn; free one engine slot while staying in range; take a step or make an edit to reconcile. **PASS:** the object appears — visible and collidable — on that first reconcile. **FAIL:** it stays invisible until leaving and re-entering range.
- [ ] **[#3](https://github.com/Gazing/peepo-mon/pull/3) Large-map admin teleport** — Put a remote player at map-local x or y ≥ 128; invoke admin teleport-to-player. **PASS:** exact target tile. **FAIL:** wrapped, wrong, or off-map landing. (Skip if the build has no suitably large map.)
